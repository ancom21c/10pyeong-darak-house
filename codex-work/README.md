# 청용리 작은 집

빌드 없이 사용하는 두 개의 단일 HTML입니다. JavaScript와 스타일은 각 페이지에 포함되어 있고, Three.js 0.180.0과 IBM Plex Sans KR은 CDN에서 불러옵니다. 인터넷 연결과 WebGL을 지원하는 브라우저가 필요합니다.

현재 디렉토리에서 다음 명령으로 열면 원도면·현장 사진 링크와 두 페이지의 저장안 공유까지 사용할 수 있습니다.

```sh
python3 -m http.server 8765 --directory ..
```

- 설계 도구: http://localhost:8765/codex-work/house-plan.html
- 현장 시뮬레이션: http://localhost:8765/codex-work/site-sim.html

같은 주소·포트의 브라우저를 유지해야 저장안을 공유합니다. HTML을 직접 열어도 화면을 사용할 수 있지만, `file://`의 로컬 저장 공유 정책은 브라우저마다 다릅니다. 사진은 `../intels`를 그대로 참조하며 필수 렌더링 자산은 아닙니다.

## 조작

설계 도구에서 층과 2D/3D를 선택합니다. 가구를 드래그하고 선택 패널에서 폭·깊이·회전을 변경합니다. 벽 가까이에서는 위치를 맞춥니다. 측정 모드에서 두 점을 선택하고, 벽 변경 모드에서는 회색 일반 벽을 선택해 이동하거나 철거합니다. 진한 외곽벽은 잠금 상태입니다. 바닥재·가구·벽 변경을 실행 취소하거나 다시 실행할 수 있습니다.

2D와 3D는 같은 메모리 설계안을 즉시 사용합니다. `설계안 저장`을 누르면 `localStorage`의 `cheongyong-house-v1`에 저장하고, 열린 현장 탭에도 저장 이벤트로 전달합니다. 현장 페이지의 `저장 설계안 반영`은 수동 새로 읽기입니다. 아직 저장하지 않은 편집은 다른 페이지에 전달하지 않습니다.

3D의 기본 장면은 외벽·창호·지붕까지 완성된 집입니다. `지붕 열기`로 본채와 증축의 실내를 확인합니다. 1인칭에서는 화면을 드래그해 시선을 바꾸고 WASD 또는 방향 버튼으로 이동합니다. 층 선택으로 시작 위치를 바꾸거나 계단을 따라 이동합니다. 다락 가구는 바닥 +2,500mm 기준에 배치되고 보이드 진입은 난간 경계에서 차단됩니다. 다락·보이드 사이에는 벽과 바닥을 만들지 않았습니다.

현장 페이지는 0–6 단계, 시간대, 자동 순항, 1인칭, 조경 이름 표시를 지원합니다. 자동 순항은 약 5.5초마다 다음 단계로 진행하며 활성 페이지에서 동작합니다. 2D와 3D 각각 PNG를 내려받을 수 있습니다.

## 도면과 현장 해석

| 항목 | 반영 및 근거 |
| --- | --- |
| 본채 | `floorplan-1f.jpg`의 7,400을 볼펜 수정 8,000mm로 변경. 원도면 깊이 4,500mm 유지 |
| 후면 | 볼펜으로 추가한 3m 구역을 8,000 × 3,000mm 검토안으로 표현. 다용도·창고·방의 용도는 필기 판독을 보완한 가정 |
| 후문 | 볼펜으로 표시된 좌측 주방 외벽 위치에 폭 900mm로 표현. 정확한 폭·문 방향은 가정 |
| 다락 | 본채 오른쪽 3,000 × 4,300mm 바닥, 왼쪽 보이드, 높이 1,050mm 난간과 계단 연결 |
| 다락 증축 | 참고 도면의 오른쪽 3,000 × 3,300mm 안을 별도로 표현. 기둥 지지와 연결 개구부는 검토용 가정 |
| 높이 | 입면의 2,300 + 1,800mm를 참고해 바닥 2,500mm·처마 4,400mm로 보정. 지붕 경사·용마루 5,350mm는 시각화 가정 |
| 공사 단계 | 형틀 사진과 타설 완료 사진이 함께 있으므로 촬영 시점이 다른 상태로 해석. 스팬덱 + 75mm RC는 사용자 지정층을 표현하며 기초 전체 상세를 뜻하지 않음 |
| 방위 | 현장 세계 좌표에서 동쪽 -X, 북쪽 -Z. 건물 정면 동향, 장변을 기초 장변과 평행하게 정렬 |
| 환경 | `GEO-NOTE.md`, 현장 사진을 우선으로 남·동 논, 서·북 산림, 남쪽 진입·곡선 도로·옹벽을 상대 배치. 필지 경계·도로 거리·고도·개울 선형은 실측값이 아님 |
| 조경 | 정면 왼쪽(북측)에 비석과 주목 두 그루. 담장 안쪽 산수유·라일락·비파·무화과·체리, 북쪽 녹차. 기존 옹벽 위 600mm 벽돌 기단 + 500mm 펜스 제안 |
| 마당 | 진입·주차부 투수 포장, 생활 마당 돌 사이 잔디, 가장자리 배수 띠. 시각화 제안이며 배수 설계는 실측 후 결정 |

내력 여부는 구조도에 표시되어 있지 않아 외곽벽을 보호하고 내부 칸막이를 편집 가능하게 두었습니다. 창호의 일부 폭·높이·위치는 도면 그림의 비례로 해석했습니다. 실내 면적은 벽 안쪽 바닥을 합산하며, 층마다 후면 또는 다락 증축 검토안을 포함합니다. 일반 벽을 변경하면 분할 면적과 합계가 다시 계산됩니다. 표시 면적은 인허가 면적이 아닙니다.

두 페이지는 독립 파일 조건을 지키기 위해 같은 설계 모델과 3D 생성 코드를 인라인으로 포함합니다. 수정 시 두 파일의 `DEFAULT`, `rooms`, `openings`, 공통 모델링 함수를 함께 반영해야 합니다. 현재 검증은 `evidence/verification.json`의 파일 SHA-256과 결합합니다. Three.js 구성은 [공식 OrbitControls 문서](https://threejs.org/docs/pages/OrbitControls.html)를 참고했습니다.

## 브라우저 검증

`tests/e2e.cjs`는 실제 마우스·버튼·폼 입력으로 편집, 저장, PNG 다운로드, 3D 동기화, 공사 단계, 자동 순항, 모바일 레이아웃을 확인하고 `evidence/`에 화면과 결과를 남깁니다. 앱 실행에는 Node나 Playwright가 필요하지 않습니다. 검증을 다시 실행할 때만 Playwright가 설치된 환경에서 다음을 사용합니다.

```sh
node tests/e2e.cjs
```

필요하면 `PLAYWRIGHT_MODULE`(모듈 경로), `BROWSER_PATH`(Chromium 실행 파일), `BASE_URL`(페이지가 있는 HTTP 경로)을 지정합니다. 소프트웨어 WebGL로 검증하며 실제 모바일 기기의 GPU 성능과 터치 체감은 별도 확인 대상입니다.
