# 청용의 집

`intels` 자료만 직접 판독해 독립 구현한 주택 설계 도구와 대지 시뮬레이션입니다. 완성된 HTML 두 파일은 빌드 없이 실행됩니다. 다른 작업 디렉터리, 다른 에이전트 결과물, 이전 세션 문서와 메모리는 참조하지 않았습니다.

## 실행

이 디렉터리에서 다음 명령으로 두 페이지를 같은 출처에서 엽니다.

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory /home/ancom/workspace/10pyeong-house
```

- 공간 설계: <http://127.0.0.1:8768/codex-work/house-plan.html>
- 대지 시뮬레이션: <http://127.0.0.1:8768/codex-work/site-sim.html>

HTML을 직접 열어도 작동합니다. 페이지 간 로컬 저장 공유는 같은 HTTP 출처에서 사용할 때를 기준으로 했습니다. 각 파일 안에 CSS·설계 데이터·JavaScript가 모두 들어 있습니다. Three.js 0.160.0과 OrbitControls는 jsDelivr, IBM Plex Sans KR은 Google Fonts에서 불러옵니다. 3D에는 인터넷과 WebGL이 필요합니다. CDN을 불러오지 못하면 안내를 표시하며 2D 편집은 계속 사용할 수 있습니다.

## 공간 설계

- 1층 / 다락 2D 평면도, 외곽 치수 mm, 순면적 자동 계산.
- 실제 크기의 기본 가구, 추가·드래그·15도 회전 손잡이·크기 조절 손잡이, 숫자 치수 편집, 벽 맞춤.
- 선택한 가구는 방향키로 50mm 이동, R로 90도 회전, Delete로 삭제.
- 두 점 사이 측정, 칸막이 이동·철거, 철거한 방 병합, 오크·타일·석재 바닥 변경.
- 취소·다시 실행 최대 60회. Ctrl/Cmd+Z 및 Ctrl/Cmd+Shift+Z. 기본 배치 복원도 취소 가능.
- 변경 사항 로컬 저장, 재로드 복원, 같은 출처의 현장 페이지 및 다른 탭과 저장 상태 동기화.
- 2D / 3D 전환, 완공 외관, 지붕 열기, 조감도, 1인칭 둘러보기, PNG 내보내기.
- 다락 바닥 +2,300mm, 1층 위 열린 보이드, 1.1m 난간, 13단 계단과 상부 참.
- 1인칭은 드래그로 시선, WASD·화살표로 이동. 실제 계단을 따라 층 높이가 바뀝니다. 다락은 바닥이 있는 영역에만 이동 가능하며 층별 벽·가구 충돌을 계산합니다.
- 모바일은 터치 가구 편집, 측정·확대, 속성 패널의 전체 가구와 증축 설정, 3D 궤도·터치 이동 버튼을 지원합니다.

## 공사 단계

| 단계 | 상태 | 기준 |
| --- | --- | --- |
| 0 | 빈 성토 대지 | 현장·GEO-NOTE의 상대 위치 |
| 1 | 기초 형틀·철근 | 사진 1~16의 과거 공정 |
| 2 | 기초 콘크리트 타설 | 기초 관련 사진, 별도 KakaoTalk 타설 후 사진 |
| 3 | 1층 경량철골 조립 | 최신 사진에서 이미 완료·고정된 하부 골조 |
| **4** | **다락 골조 상승** | **사진 17~21, 사용자 확정 2026-10-04. 기본 표시 단계** |
| 5 | 지붕·외장 | 향후 공정의 설계 시각화 |
| 6 | 창호·마감·조경·선택한 증축안 | 완공 계획안 |

4단계는 1층을 처음 조립하는 상태가 아닙니다. 하부 프레임이 완료된 위로 다락 기둥과 상부 트러스가 올라와 전체 높이에 도달한 모습입니다. 7단계 개수를 유지하기 위해 기초 형틀·철근을 하나의 단계로 묶었습니다. 후면 및 다락 증축은 6단계에만 표시합니다.

단계 슬라이더·버튼, 현재 현장 바로가기, 공정 애니메이션, 순항 카메라와 5.5초 간격의 단계 자동 진행을 제공합니다. 단계 선택이나 장면 조작으로 자동 진행을 멈출 수 있습니다. 시간대 슬라이더는 태양 위치·빛 색·그림자를 바꾸며, 날짜별 정밀 일조 계산을 대신하지 않습니다.

## 자료 해석과 가정

| 항목 | 적용 | 근거 / 확실성 |
| --- | --- | --- |
| 본체 | 8,000 × 4,500mm, 36.00m² 외곽 | 1층 도면의 7,400 → 8,000 볼펜 수정 + 사용자 지시 |
| 후면 | 본체 뒤 8,000 × 3,000mm 증축 스케치. 기본 켜짐, 끌 수 있음 | 볼펜 3m 및 세탁·홀·방 그림을 해석한 **계획안**. 본체 기초 공정에 합치지 않음 |
| 후문 | 뒤쪽 볼펜 스케치의 좌측, 후면 증축안을 끄면 본체 좌측 뒤 | 도면의 추가 문 스케치. 상세 위치·폭 850mm는 가정 |
| 구획 폭 | 오른쪽 방폭 약 3m를 우선하고 남은 폭을 재배분 | 볼펜 2,600 → 3,000. 수정 수치 합과 외곽 8,000이 정확히 일치하지 않아 외곽을 우선 |
| 1층 / 다락 높이 | 2,300 / 1,800mm | 정면도 수치 해석. 다락 바닥 75mm RC, 스팬덱은 사용자 요청의 계획 사양 |
| 지붕 | 본체 박공, 용마루 +5,000mm, 금속 마감 | 박공 형상은 사진 17~21. 용마루·구배는 실측 없음, 가정. references 지붕 이미지는 재료·증축 치수 참고 |
| 기본 다락 | 오른쪽 바닥 + 계단 참, 왼쪽 거실 위 보이드 | `plans/floorplan-attic.jpg`와 수정 폭을 함께 반영. 다락/보이드 경계에 벽 없음 |
| 다락 증축 | 3,000 × 3,300mm, 총 9.90m², 지지 기둥 포함 | 사용자 요청. 실내 8.68m². 문 연결·지붕 상세는 계획 가정 |
| 벽·개구부 | 100mm 벽, 도면 위치 기준 문·창, 미표기 치수 보완 | 도면과 사진에 없는 문·창 세부 치수는 가정 |
| 구조 편집 | 외곽 경량철골은 잠금, 내부는 편집용 칸막이 | 구조 검토 자료가 없어 보호 구조로 보수적으로 분류. 실제 내력벽 판정을 확정한 도구가 아님 |
| 대지 방향 | 정면 동향, 본체와 기초 패드 평행 | 사용자 확정 |
| 주변 | 남·동 논, 북·서 산림, 남측 모서리 진입로, 곡선 도로·블록 옹벽·돌담·전봇대 | `GEO-NOTE.md`, 현장 사진, 지도 이미지의 상대 배치 |
| 대지 치수 | 성토 패드·낙차·도로·배수로·산 능선은 저폴리 재해석 | 측량 없음. 필지 면적·경계 좌표를 지도에서 수치화하지 않음. 성토 약 1.1m 및 기초 상단 +0.25m는 가정 |

후면 증축안을 켠 기본 1층 외곽은 60.00m²이며, 벽 두께를 제외한 실내 순면적은 54.86m²입니다. 증축안을 끄면 본체 36.00m² 범위만 사용합니다. 방 면적은 외곽 벽 안쪽을 격자로 분할하고 활성 칸막이 두께를 제외한 연결 영역을 합산합니다. 문 개구부는 방 경계로 유지합니다. 칸막이를 철거·이동하면 다시 계산됩니다. 이는 법정 건축면적·다락 산입 면적의 판정이 아닙니다.

`plans/original-floorplan.jpg`는 다른 치수·언어의 큰 평면도로 판단해 이 주택의 구조 근거로 사용하지 않았습니다. 건축허가도면의 방위·배치는 계획 참고이며 현장 사진과 사용자 확정을 우선했습니다. 건물-비석 이미지는 건물 좌측 관계만 사용했습니다.

## 조경안

기본 마당은 바닥돌과 잔디 줄눈입니다. 출입·비석 접근·주차 동선은 촘촘한 돌 포장으로 두고, 전체 시멘트·잔디 안도 비교할 수 있습니다. 완공 조경에는 정면 좌측 비석과 작은 주목 두 그루, 경계의 산수유·라일락·비파·무화과·체리, 북측 녹차 생울타리를 배치했습니다. 기존 옹벽과 별도로 벽돌 0.6m + 펜스 0.6m, 총 1.2m 경계를 제안합니다. 토양·성목 간격·배수·수종 적합성은 자료로 확정할 수 없어 현장 확인 전의 제안으로 표시했습니다.

## 검증·수정

2026-10-09 최종 브라우저 동작 검증 27개가 통과했고 정상 온라인 실행 콘솔 오류는 0건입니다. 계단 연속 상승, 보이드 추락 방지, 페이지 간 저장 동기화, 모바일 실제 터치와 CDN 오류 대응을 포함합니다. 브라우저 검증 결과는 `evidence/verification.json`, 대표 화면은 `evidence/*desktop.png`, `evidence/*mobile.png`, PNG 내보내기 결과는 `evidence/verified-*-export.png`에 있습니다. 최종 HTML SHA-256과 사용 자료의 해시는 `evidence/delivery-manifest.json`에 남깁니다. 실제 GPU나 실제 휴대폰 시험을 의미하지 않으며 Chromium의 데스크톱·모바일 터치 환경과 소프트웨어 WebGL로 확인했습니다.

최종 HTML은 그대로 수정할 수 있습니다. 작성 과정의 원본은 `evidence/implementation/`에 있으며 `python3 evidence/assemble.py`로 두 HTML을 같은 모델에서 다시 생성할 수 있습니다. **이 스크립트와 원본 폴더는 페이지 실행에 필요하지 않습니다.**
